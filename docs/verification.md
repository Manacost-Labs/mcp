# Повторная проверка production

## Возврат в локальный Codex — версия 1.2.4

В Chromium воспроизведена причина `Expired or invalid consent`: `form-action
'self'` блокировал переход после POST на локальный callback. Первая отправка
создавала код, повторная отправляла уже использованное согласие. Отдельно
`Referrer-Policy: no-referrer` приводил к `Origin: null` у обычной HTML-формы.

Страница согласия разрешает возврат только на origin зарегистрированного callback
и использует `same-origin` для referrer. На ней отключено повышение HTTP до HTTPS,
чтобы локальный HTTP listener мог получить код. Запрет скриптов и фреймов,
проверки Origin, cookie, администратора, PKCE и одноразовости сохранены.

**32 теста**, typecheck и сборка прошли; Semgrep: 0 находок и 0 ошибок.
В настоящем Chromium на изолированной фикстуре проверен переход с HTTPS-страницы
на HTTP `127.0.0.1`, получение callback и обмен кода с PKCE: ответ token endpoint
`200`, access token выдан. Продакшн-сессия пользователя для теста не использовалась.

## Защищённая сессия HearthPulse — версия 1.2.3

Работающий HearthPulse использует `__Host-manacost_auth_token`; MCP прежде искал
только старое имя, из-за чего вошедший администратор вновь видел страницу входа.
Новое имя сохраняется при проверке identity и внутри зашифрованного grant.
**30 тестов**, typecheck и сборка прошли. Проверены consent, access, refresh,
снятие admin и отсутствие fallback при пустой/некорректной защищённой cookie.
Старые grants и login cookies остаются совместимыми, если новой cookie нет.

## Вход с локального ПК — версия 1.2.1

Исправлен неверный адрес формы HearthPulse: `/profile/` отвечал 404, действующий
маршрут — `/?login` (200). Query разрешён только у login URL; проверка того же
origin и ограничения URL источников сохранены. **27 тестов**, typecheck и сборка
прошли, включая проверку ссылки входа и сохранения OAuth continuation.
Первый вход реального пользователя в браузере не выполняется автоматически.
